# Chart syntax

Charts are UTF-8 JSON. The game and editor use the same `ChartLib` validator and plugin registry. Times are chart seconds; chart time equals audio time plus `offset`. The original tutorial is generated by `ChartLib.demo()`; `songs/_demo/chart.json` materializes that chart for editing.

## Minimal example

```json
{
  "title": "My Song",
  "audio": "audio.wav",
  "bpm": 120,
  "offset": 0,
  "timing": [{"t": 0, "beat": 0.5, "meter": 4}],
  "lights": [{"t": 0, "id": 0, "type": "on", "x": 0.25, "w": 0.2666666667, "a": 1, "auto": true}],
  "notes": [{"t": 3, "light": 0, "u": 0.5625, "kind": "tap", "k": 2}],
  "fx": [],
  "meta": {}
}
```

Place this in `songs/<dir>/chart.json` beside the audio. Add a matching entry to `songs/index.json` to include it in the ordinary game list, or use the editor to create/import a song and add it to the list. The public index is initially empty; tutorial and plugin-demo access remain available.

## Tracks and notes

Legacy light events use `{t,id,type,x,w,a,dur,ease,tint,auto,from}`. `type` is `on`, `sweep`, `pulse` or `off`; `x` and `w` are normalized to the 15-unit keyboard span. `a` is opacity. `sweep` interpolates geometry with `inout`, `linear`, `in` or `out` easing. A quick reach is a sweep with `dur: 0.09, ease: "out"`. Optional `tint` is 0..9.

Non-automatic events create space/pedal cues. `from` can be `L`, `R` or `LR` (default `LR`); simultaneous events share a cue. Automatic staging events use `auto: true`. Transparent carriers (`a: 0`) still carry and judge notes. Tracks must exist early enough for their notes' approach and remain alive through a hold's end. The editor rejects orphaned notes and incompatible seams atomically.

Notes use `{t,light,u,kind,dur,path,k,nw,big,ex,grow}`. `light` references the carrier's ID; `u` is its normalized horizontal position. `kind` is `tap` or `hold`; holds have a positive `dur` in seconds. `k` is an optional home-row fingering index 0..10, not a restriction on which key can hit. `big: true` fills the track; `ex: true` is a yellow note. `nw` controls note width. Hold `path` points contain relative seconds, horizontal position and width. Plugin fields and their constraints are described in the plugin guide.

A press on any key within the track span can hit a note. A yellow note can be caught by any key already held in its track. Hold ticks are graded by the time released inside the track, so switching keys is supported. Exact timing windows, cut windows, slap guard and snap behavior are defined by the shared game implementation and asserted by focused rule tests; this preparation does not change them.

## Musical positions and IDs

Numeric MCP positions are chart seconds. Strings use `bar.beat[+n/16]`; bar 0 starts at `timing[0].t`, with 1-based beats. Bar -1 is the pickup. Fractions such as `+1/12` are supported. For example, with a 120 BPM timing point at 0, `"2.1"` means 4 seconds. Ranges include their start and exclude their end. Tempo-map `beat` is seconds per beat, not BPM.

Editor `notes` returns raw array IDs, even when the runtime sorts notes by time. Track event array indices and track IDs are distinct. Read the current revision and object IDs before editing; do not reuse IDs from an unrelated chart or analysis reference.

## Camera, stage and plugins

`fx` contains timed effects; `meta.breath` contains `{t0,dt,energy}` and `meta.mod` entries use `{t0,t1,kind,dir}` with kind `beat`, `breath`, `sway` or `twitch`. The editor camera tools expose supported channels, numeric values, units and vocabulary. Use these tools or the plugin field declarations rather than inventing engine fields.

Song packs may declare `plugins` and provide local plugin manifests, textures, declarative effects or scripts. Script packs require explicit human trust. See [the plugin author guide](../game/PLUGINS_API.md) and [Chinese guide](../game/PLUGINS_API.zh-CN.md); `songs/_plugin_demos/` contains executable examples using the original demo audio.

## Editor and verification

The current charter is the native Godot editor with a localhost Streamable HTTP MCP server. Start it after `python tools/sync_core.py`; see [editor setup and tool reference](../charter/README.md). Older Python/stdio music-analysis services are not part of this public repository. Optional `analysis.json` data is read when supplied; do not treat synthetic test metadata as measured audio analysis.

Edits require `expected_revision` and are atomic. Saving from MCP requires user opt-in; `.read-only` protects a song directory. Use a separate working copy for experiments. Undo/redo, simulations, song-local versions and plugin inspection are exposed through the same editor tools. Version initialization and commits require explicit UI actions or opt-ins.

Run `python tools/run_tests.py` from the repository root. Test fixtures and seeded replays live under `game/tests/fixtures/` and are excluded from exports. Deterministic numeric/render comparisons are documented in [baselines](../game/tests/baselines/README.md). Release tools perform muted, headless or offscreen verification.

## Syntax v3: tracks are the core (2026-10-16)
Everything is a track (a light) and notes always ride their track. A light event may carry `a`, the track's opacity
0..1 (a sweep interpolates it like x / w). A track at `a: 0` is invisible but still carries and judges its notes, so
"the light moves while the note stays" is written as a transparent note track plus a visible track performing next to
it; "the light moves with the note" is just moving the note's track. v3 charts express all motion as track events
(no `meta.mod`); drawing depends only on `a` and `tint` (glass brightness ~ a, edges ~ a^2, judgement stroke ~ a).
VOEZ mapping: Start/End = on/off, Move + Scale = sweep (x, w, ease), ColorChange = tint, plus `a`.
